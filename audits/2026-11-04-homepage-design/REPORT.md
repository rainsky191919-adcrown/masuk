# Masuk? 首页设计与体验审计

日期：2026-11-04（马来西亚时间）
目标：[正式版公开首页](https://my.pintumasuk.workers.dev/)
本次仅审计；未修改网站源代码、配置或线上数据，未执行新增、编辑、举报、登录或退出操作。浏览器继承了已有登录，因此截图包含已登录导航；普通游客导航未验证。

## 结论

深色视觉、荧光绿强调色和门禁情报定位具有辨识度，搜索与基础筛选可用。当前最影响体验的是：手机首屏信息顺序、未确认资料的评分表达，以及筛选无结果时的错误引导。建议保留品牌视觉，优先调整信息结构和状态文案。

审计目标：让司机在出发前或安全停靠时，快速找到地点，区分已知规则与待核实信息，再选择查看详情或导航。

## 检查步骤与截图

### 1. 桌面首页：可用，有信息一致性问题

最终 URL 为 https://my.pintumasuk.workers.dev/，标题为 Masuk? · Guardhouse Intel。加载后为 21 个地点，桌面双列卡片。主标题明确，搜索入口明显；但页头 KLANG VALLEY 与区域选择器 Skudai, Johor 及页脚 Skudai only 不一致。状态卡展示 Supabase · 云端资料，提供的是实现信息，无法帮助司机判断资料是否新鲜或可信。

![01 桌面首页](E:/wanmaiwangye/audits/2026-11-04-homepage-design/01-desktop-home.png)

### 2. 手机首屏：需优先优化

以 390 × 844 手机视口检查。品牌、标题、说明、独立状态卡、搜索、区域、两行筛选依次占据首屏；第一张地点卡只露出标题和状态，具体门禁规则需要滚动才能阅读。搜索与结果的距离偏大。

![02 手机首屏](E:/wanmaiwangye/audits/2026-11-04-homepage-design/02-mobile-home.png)

### 3. 手机地点卡片：信息完整，但阅读与判断成本高

卡片同时展示 UNCONFIRMED、待确认、待司机实测、0 人认可、0 位司机反馈，以及五色友好度条。文字说明诚实，但五色条没有明确的当前评分，可能被误认为已有评分或可点击筛选。公开房产设施说明较突出，司机真正需要的访客登记要求仍然未知。底部 Maps、修改、复制较拥挤，修改与复制出现换行。

![03 手机地点卡片](E:/wanmaiwangye/audits/2026-11-04-homepage-design/03-mobile-card.png)

### 4. 友好度筛选无结果：操作成功，恢复引导需优先优化

点击“很顺畅”后显示 0 条结果。页面使用“这个区域还没有匹配的记录”，并将“新增这间公寓”作为醒目的操作。此次没有输入具体公寓名称，因此新增指向不明确；已有地点可能只是尚无该等级评分，并非缺少地点。点击“清空筛选”后恢复 21 条结果，恢复功能正常。

![04 筛选无结果](E:/wanmaiwangye/audits/2026-11-04-homepage-design/04-filter-empty.png)

### 5. 名称搜索：通过基本检查

输入 Bukit 后得到 2 个匹配地点，并出现清除搜索、重置筛选入口。名称匹配与计数更新可用。本次没有验证拼写容错、别名、所有地址匹配或多语言搜索；不将这些能力视为已通过。

![05 名称搜索结果](E:/wanmaiwangye/audits/2026-11-04-homepage-design/05-search-results.png)

菜单能展开并显示查地点、报一个新点、后台管理；关闭也正常。展开时视觉图标变为关闭，但可访问名称仍为“打开菜单”，未发现 aria-expanded 属性。已关闭菜单、清空搜索并恢复原视口。

## 按优先级排序的优化建议

P1 表示优先解决核心任务或误导风险；P2 表示随后改善清晰度与操作体验。以下均为建议，未实施。

| 优先级 | 证据 | 问题与影响 | 优化建议 | 后续验收方式 |
|---|---|---|---|---|
| P1 | 02、05 | 手机首屏在阅读规则前需要滚动；独立状态卡占用空间 | 将搜索移到标题后；把地点数量与覆盖区域合并为紧凑一行；缩短介绍；将次要筛选收进可展开区域 | 在同一手机视口下，默认首页能够看到第一条关键规则摘要 |
| P1 | 03 | 待确认卡片仍展示完整五色等级条，易被误读为有效评分 | 无评分时用单一“尚无司机评分”状态替代等级条；有有效评分才显示一个明确的当前等级，并保留文字标签 | 未确认与已评分状态无需依靠颜色即可区分 |
| P1 | 04 | 等级筛选无结果，却突出新增公寓，可能诱发重复录入 | 明确提示“当前筛选下暂无地点”；优先“清除友好度筛选”；仅在按名称查找确实无结果时提供“补充这个地点” | 用户能理解是筛选无结果，并一键恢复已有记录 |
| P1 | 01、02，页脚 DOM | KLANG VALLEY 与 Skudai 覆盖描述冲突 | 统一为实际覆盖区域；若未来扩区，使用动态区域名称 | 页头、区域选择器、结果说明、页脚保持一致 |
| P2 | 01、03 | 公共设施说明占据显著位置，关键访客流程未知；0 认可却用绿色勾号 | 优先展示“是否可进、是否登记、是否联系住户”等已知项；未知项明确标注，不推断；零认可用中性样式；区分“资料导入时间”和“司机实测时间” | 扫描卡片就能区分已知、未知和司机验证状态 |
| P2 | 02、03，尺寸读取 | 筛选字体 11px、按钮高 30px；Maps 字体 9px、高 25px；修改宽约 32px且换行 | 关键操作采用更易读字号，建议主要触控区域接近 44 × 44px；减少底部并列操作，将编辑收进次级入口 | 手机上关键按钮不挤压换行，易读且容易准确点击 |
| P2 | 02、04、06，DOM | 筛选按钮缺少可编程的选中状态；菜单缺少展开状态且名称不随关闭状态变化 | 筛选使用 aria-pressed 或合适的单选语义；菜单增加 aria-expanded 和受控区域关系，并同步打开/关闭名称 | 辅助技术可识别当前筛选与菜单开关状态 |
| P2 | 01、02 | 状态卡突出 Supabase，司机缺少可用性信息 | 用真实数据展示“覆盖 Skudai · 21 个地点”，有可靠数据时再显示最近现场验证情况 | 状态区回答覆盖范围、内容数量与验证情况，不制造可信度 |

## 值得保留的部分

- 深色背景、青色辅助信息与荧光绿品牌强调色具有一致性。
- 搜索框、区域选择器有可访问名称；页面具有主标题与地点二级标题。
- “待确认”“待司机实测”没有把公开房产资料冒充现场门禁结论，应保留这种透明表达。
- 基本搜索、筛选、清空和手机菜单在本次检查中均可使用。

## 证据边界

本次检查首页及其搜索、筛选、卡片和导航菜单，未进入管理后台，未测试详情、导航跳转、复制、内容提交或权限流程。未使用真实手机触屏或屏幕阅读器，未做完整键盘遍历、精确颜色对比度测量、200% 缩放、性能测试或 WCAG 合规认证。小字号与触控尺寸为实测体验风险，不据此直接宣称 WCAG 不合格。未确认全部 21 个地点的评分与资料质量。

建议下一轮先评审三个调整：压缩手机首屏、简化未评分卡片、修正筛选无结果的主操作。
